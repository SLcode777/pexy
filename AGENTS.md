# AGENTS.md

Instructions for AI coding agents working on Pexy. Humans: see [README.md](README.md) and [CONTRIBUTING.md](CONTRIBUTING.md).

## What Pexy is

A free AAC (Augmentative and Alternative Communication) app for people with speech disorders, mostly autistic children. The user taps a pictogram, picks a sentence, and the phone speaks it. Users rely on habits: **a change that moves, renames or removes something they know can genuinely distress them.** Prefer adding over changing, and never remove user-facing content without being asked.

## Stack

React Native 0.81 + Expo SDK 54 (new architecture), TypeScript, Expo Router, SQLite via `expo-sqlite` + Drizzle, i18next (French and English), `expo-speech` for text-to-speech. Package manager: **pnpm**. Path alias: `@/` = repository root.

## Commands

```bash
pnpm install
pnpm start            # Expo dev server, opened with Expo Go (SDK 54)
pnpm test             # data tests (node:test, no dependencies, under a second)
pnpm typecheck        # tsc --noEmit, must report 0 errors
pnpm lint             # expo lint, must report 0 errors (warnings are tolerated)
pnpm update-pictos    # after adding images in assets/pictos/
```

Run all three before saying a change is done; CI runs them on every pull request (`.github/workflows/ci.yml`).

`pnpm test` checks the **data**, not the screens (`tests/data.test.mjs`): valid JSON, unique pictogram ids, French/English sentences mirrored, punctuation rules, image files present and registered, identical keys in both locale files, and **no known sentence removed** (compared to `tests/baseline-sentences.tsv`). There are no UI tests: after the checks pass, tell the human exactly what to test in the app, because you cannot see the screen.

Do not make a test pass by weakening it. In particular, never run `pnpm test:update-baseline` or add an entry to `MIRROR_EXCEPTIONS` unless the maintainer asked for that specific change.

| Path | Content |
| --- | --- |
| `app/` | Screens (Expo Router). `app/(main)/` holds the tabs. |
| `components/` | Shared UI. `PictogramImageMap.ts` is **generated**, never edit it by hand. |
| `constants/` | Categories, colors |
| `data/pictograms/*.json` | Built-in pictograms and sentences, one file per category |
| `assets/pictos/<category>/*.webp` | Pictogram images |
| `lib/db/` | `schema.ts` (Drizzle), `index.ts` (table creation + migrations), `operations.ts` (queries) |
| `lib/pictograms.ts` | Loading built-in and custom pictograms |
| `lib/backup.ts` | Export / import of user data |
| `locales/{fr,en}/translation.json` | UI strings |
| `tests/` | Data tests and the sentence baseline |
| `android/` | Generated by `expo prebuild`, git-ignored. Do not edit. |

## Rules

### Content
- **Do not edit sentences in `data/pictograms/`** unless the maintainer explicitly asks. They are curated by hand.
- If asked to work on them: never delete a sentence (move less useful ones to the end of the list), keep `fr` and `en` lists mirrored (same count, order and emoji), French uses "tu" and a space before `?` and `!`, English has no space before them.

### Two sources of pictograms
Built-in pictograms come from the JSON files; **custom pictograms live in SQLite** (`custom_pictograms`, images under `documentDirectory/custom_pictograms/`). Any feature that lists, searches or favorites pictograms must handle both: use `loadCustomPictograms()` alongside `loadAllPictograms()` from `lib/pictograms.ts`.

### The `image` field
A pictogram's `image` is one of: an emoji, an `assets/...webp` path, or a `file://` URI. Always render it with `<PictogramImage>` (or `<PictogramCard>`), never as raw `<Text>`.

### Interface
- Every user-visible string goes through `t()` and exists in **both** locale files.
- Icons are emoji, consistent with the rest of the app. An icon-only button needs an `accessibilityLabel`.
- Touch targets stay large (about 56 px): users are children, some with motor difficulties.
- Destructive actions ask for confirmation.

### Data
- **Offline first, no network calls, no analytics, no accounts.** Nothing leaves the device.
- Schema changes: update `lib/db/schema.ts` **and** add an idempotent migration in `lib/db/index.ts` following the existing `PRAGMA table_info` + `ALTER TABLE` pattern. Existing users' data must survive the update.
- New user data must be included in `lib/backup.ts` (export and import), and backups made by older versions must still import.
- Keep a custom pictogram's `customId` stable: favorites and custom phrases are attached to it.

### Code
- Code, comments and commit messages in English. Keep comments short.
- Match the surrounding style. Keep changes scoped to the task: no drive-by refactors, no new dependencies without asking.
- Prefer modules that work in Expo Go. A native module outside the Expo SDK needs the maintainer's agreement.
- Never commit secrets, `.env*` files or keystores.

## Git

Work on a branch, one topic per pull request, reference the issue (`Closes #N`). Do not commit, push or open a pull request unless the human asks you to.
